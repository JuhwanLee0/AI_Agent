# 바이브 코딩 및 AI 생성 앱 보안 필수 점검 가이드 (아는개발자 레퍼런스)

AI 앱 개발 시 가장 빈번하게 발생하는 보안 취약점과 데이터베이스/스토리지 침해 사고를 사전에 차단하기 위한 개발본부 필수 점검 체크리스트입니다.

---

## 1. API 키 및 환경변수(Secret Key) 은닉 및 관리
- **.env 파일 분리 및 .gitignore 필수 등록**: API 키, DB 패스워드, 마스터 키는 절대 소스코드에 하드코딩하지 않고 `.env`로 관리하며, 저장소에 커밋되지 않도록 `.gitignore`에 등록합니다.
- **프론트엔드 API 키 노출 금지**: `NEXT_PUBLIC_` 또는 클라이언트 번들에 Secret API 키(OpenAI, Supabase Service Role Key, 결제 Secret Key 등)를 절대 노출하지 않습니다. 외부 API는 반드시 Next.js API Routes 또는 백엔드 서버(FastAPI, Express 등)를 거쳐 프록시 호출합니다.
- **AI 채팅창/프롬프트 유출 방지**: 프롬프트나 인수인계 메시지, 로그에 실제 Secret Key가 평문으로 노출되지 않도록 마스킹 처리합니다.
- **노출 시 즉각 조치 및 수명 관리**: 만약 키가 외부에 노출되었다면 즉시 폐기(Revoke) 및 재발급하며, 임시 토큰은 유효기간(TTL)을 짧게 유지합니다.

---

## 2. 데이터베이스(Supabase / PostgreSQL) RLS 및 권한 통제
- **RLS (Row Level Security) 필수 활성화**: 모든 테이블에 대해 RLS(`ENABLE ROW LEVEL SECURITY`)를 필수로 적용하여 무단 SELECT/INSERT/UPDATE/DELETE를 원천 차단합니다.
- **관리자 키(Service Role Key) 노출 금지**: Service Role Key는 RLS를 우회하므로 클라이언트에 절대 전달하지 않고 백엔드 내부에서만 제한적으로 사용합니다. 클라이언트는 Anon Key만 사용합니다.
- **세부 RLS 정책(Policy) 작성**:
  - `auth.uid() = user_id` 조건을 통해 본인 데이터만 조회/수정/삭제 가능하도록 잠금.
  - 관리자 전용 테이블은 별도 역할(Role) 검증 로직을 정책에 명시.

---

## 3. 파일 저장소(Storage 버킷) 보안
- **버킷 Public 공개 금지**: 버킷을 무조건 Public으로 열지 않고 Private으로 기본 설정합니다.
- **UUID 기반 파일명 난수화**: 파일명에 유저 식별자나 원본 파일명이 그대로 노출되지 않도록 UUID/랜덤 해시를 사용합니다.
- **서명된 임시 URL (Signed URL) 발급**: 권한이 있는 사용자에게만 제한된 유효시간(예: 5분~1시간) 동안 접근 가능한 서명된 URL을 서버에서 동적으로 발급합니다.

---

## 4. 결제 및 비즈니스 로직 보안
- **클라이언트 결제 금액 위변조 검증**: 프론트엔드에서 넘어온 결제 금액(Amount)을 그대로 신뢰하지 않고, 백엔드 DB의 실제 상품 가격과 대조 검증 후 결제 승인 API를 호출합니다.
- **API 타임아웃 및 재시도(Retry) 제어**: 외부 결제/AI API 호출 시 적절한 타임아웃과 멱등성(Idempotency) 키를 적용하여 중복 결제/중복 차감을 방지합니다.
